# Classroom Student Usability Test

Purpose: verify that students can use the PC Hardware Atlas without developer guidance. This is a human classroom gate; automated browser tests do not replace it.

## Participants
Use 5–10 students from the intended class. Include students with different English confidence levels and, where possible, different familiarity with computers.

## Teacher rule
Give only the task wording below. Do not point at buttons or explain where controls are unless the student has reached the intervention threshold. Record every intervention.

## Tasks
1. From the Computer Lab, connect the keyboard to the computer.
2. Open the PC explorer and find RAM. Explain in one short sentence what RAM does.
3. Return to the Computer Lab and open Laptop Lab.
4. Find the SSD and inspect where it sits.
5. Use the laptop teardown to unplug the battery cable without clicking directly on the 3D cable.
6. Return to the Computer Lab and open Build a PC.
7. Start assembly practice and place the first part without dragging it.
8. Open Task Manager and complete one challenge.
9. Return to the Computer Lab without using the browser Back button.

## Record for each task
- Completed without help: Yes / No
- Time to completion
- Wrong turns
- Student words when confused
- Teacher intervention required
- Control/label that caused the problem
- Device model / ChromeOS version

## Intervention threshold
Allow the student to explore for up to 90 seconds. If they are stuck, give one neutral hint such as “Look for a button that matches the task.” Do not name the exact button until the second intervention.

## Pass criteria
- At least 80% of students complete every core task without a second intervention.
- No task produces the same dead end for 3 or more students.
- No student is forced to use precise 3D clicking or dragging when a keyboard/button alternative is expected.
- Students can correctly explain RAM and storage at an age-appropriate level after using the activity.
- No crash, blank canvas, lost-progress loop or navigation trap occurs during the test.

## Failure handling
A repeated confusion is a product issue, not a student error. Record it, fix the interface or wording, rerun the affected task with a fresh student group, and attach the result to the school-readiness audit.
